Talk · August 2026

Durable graphs for
long-running agents.

A ten-minute talk on Smithers — a durable control plane for coding agents, where a workflow is a TypeScript graph that runs for minutes or days, persists every finished node, and survives the process that started it. The talk is short on purpose. Everything it had to cut lives below.

The deck

Smithers — durable graphs for long-running agents

28 slides — 24 in the talk, four appendices behind them. Arrow keys to move, p for presenter notes, c for the comment drawer. Best read after the talk, or instead of it.

Appendices

Four documents, each answering one question the talk raises and does not have time to finish. They are written to be re-read, not projected.

Appendix A

The CLI, one page

Every smithers command in v0.31.0, grouped by what you are trying to do: run a workflow, observe it, control it, move backwards through it. Plus what smithers observability actually starts, and where its edges are.

Read this when you want to know whether the thing you need already exists.

 Appendix B

Human decisions in workflow UIs

An approval gate renders nothing — it persists a row and parks the run. This is how that row reaches a browser: the two RPC methods, the exact payloads, why <Approval> is a three-shape funnel rather than a form, and how to get a genuinely arbitrary payload back out of a human.

Read this before you build a UI on top of a gate.

 Appendix C

The presenter runbook

How the three live demos were actually staged: what to pre-warm, what to type, what to say, and — the useful part — what does not work. Every measured caveat is in here, including the one that killed a planned slide.

Read this if you want to run the same demos, or if you enjoy watching a demo get de-risked.

 Appendix D

Why these three demos

The design pass behind the example repos: the constraint that each demo must produce work that genuinely needs the feature it shows, the shape of all three, and the five ideas that were considered and cut, with reasons.

Read this if you are choosing demos for a talk of your own.

The three demo repos

Each one shows exactly one capability and is independently clonable — its own package.json, its own bun test, its own seeded .smithers/ pack. "Copy this folder" is the intended takeaway. Each carries a DEMO.md with the exact command order.

On the numbers in these pages. Every command, flag, port, node id, event name and measured figure was re-checked against a live smithers@0.31.0 install on 11 August 2026 — the CLI's own --help and --schema output, the bundled llms-full.txt, the observability Compose file, and real runs of the three demo repos. Where a feature does not work, these pages say so and say how it was tested. The most load-bearing example: OpenTelemetry metrics and logs reach the local collector, but spans do not reach Tempo, so there is no trace waterfall to show. A planned slide died of that, and the appendices explain why.
